# Security-ревью

Ищи конкретные, эксплуатируемые проблемы — не общие пожелания «будь
осторожнее». Для каждой находки: точное место (файл:строка), сценарий
эксплуатации (какой вход или условие приводит к проблеме), серьёзность.

Приоритетные классы (не исчерпывающий список, но с них начинай):

- инъекции (SQL, команда оболочки, путь файловой системы —
  конкатенация недоверенного ввода без экранирования/валидации);
- утечка секретов (значения в логах, ошибках, коммитах, дефолтных
  конфигах);
- отсутствующая или неверная проверка прав доступа перед действием;
- небезопасная десериализация недоверенных данных;
- гонки при работе с файлами/состоянием без блокировок там, где они
  нужны.

Не находка: стилистические предпочтения, отсутствие комментариев,
«было бы лучше, если». Это ревью безопасности, не ревью кода целиком.

Если находок нет — так и скажи прямо, не придумывай проблему ради
отчёта.
