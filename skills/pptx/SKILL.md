# Создание, редактирование и анализ PPTX

`.pptx` — это ZIP-архив из XML-файлов. Выбирай подход по задаче:

| Задача | Подход |
|---|---|
| **Создать** новый дек | Написать скрипт на `pptxgenjs` — см. подводные камни ниже |
| **Редактировать** существующий дек или собрать из шаблона | unzip → правка `ppt/slides/slideN.xml` → zip |
| **Прочитать** содержимое | `markitdown deck.pptx` (по одному блоку на слайд под маркерами `<!-- Slide number: N -->`); визуальная сетка: `python scripts/thumbnail.py deck.pptx` |

## Скрипты

Пути указаны относительно каталога этого скилла. Всё остальное — обычный Python, `node` или shell.

| Скрипт | Что делает |
|---|---|
| `scripts/thumbnail.py deck.pptx [prefix]` | Подписанная сетка всех слайдов, для выбора макетов шаблона. Только `.pptx`. Передавай `prefix` — по умолчанию `thumbnails`, что перезаписывает сетки любого другого дека, обработанного в том же каталоге |
| `scripts/add_slide.py unpacked/ slide2.xml [--after slideN.xml]` | Дублировать слайд (или `slideLayoutN.xml`) со всей учётной рутиной пакета. Также принимает `.pptx` напрямую с `-o out.pptx` |
| `scripts/clean.py unpacked/` | Удалить слайды, медиа и rels, на которые больше нет ссылок. Запускай **после** того, как `<p:sldIdLst>` финализирован |
| `scripts/office/validate.py deck.pptx [--original src.pptx]` | Проверки схемы, связей, content-type, диаграмм и слайдов; каждый сбой называет своё исправление. Передавай `--original` для любого дека из шаблона — он берёт за базу проверки схемы по шаблону, чтобы собственные XSD-ошибки шаблона не читались как твои |
| `scripts/office/soffice.py --headless --convert-to pdf deck.pptx` | Обёртка LibreOffice — голый `soffice` зависает в этой песочнице |

## Создание через pptxgenjs — подводные камни

`pptxgenjs` предустановлен — не запускай `npm install` заранее; пиши скрипт и вызывай `require('pptxgenjs')` напрямую. Только если require падает: `npm install pptxgenjs`. Модель знает API; вот типичные ловушки:

- **Задавай `pres.layout` до добавления слайдов.** Холст по умолчанию — `LAYOUT_16x9` = **10" × 5.625"**, а не 13.3" в ширину. Координаты за краем записываются, а не обрезаются — фигуры просто нет на слайде. (`LAYOUT_WIDE` — 13.3" × 7.5".)
- **Hex-цвета: никогда `#`, никогда 8 цифр.** `color: "FF0000"`. И `"#FF0000"`, и альфа, зашитая в hex (`"00000020"`), **портят файл**. Для полупрозрачности: `transparency: 0-100` у заливок и изображений, `opacity: 0.0-1.0` у теней — каждый параметр молча игнорируется у другого типа.
- **pptxgenjs мутирует объекты опций на месте** (конвертирует значения в EMU при первом использовании). Никогда не дели один объект `shadow`/опций между двумя вызовами `add*` — строй свежий объект каждый раз.
- **`offset` тени должен быть ≥ 0** — отрицательный offset портит файл. Чтобы отбросить тень вверх, используй `angle: 270` с положительным offset.
- **`letterSpacing` молча игнорируется** — настоящая опция — `charSpacing`.
- **Списки:** `bullet: true` у каждого элемента, никогда буквальный `•` (даёт двойные маркеры). Ставь `breakLine: true` на каждом элементе массива, кроме последнего. Разделяй маркированные абзацы через `paraSpaceAfter`, а не `lineSpacing` (огромные зазоры).
- **Один `new pptxgen()` на выходной файл** — никогда не переиспользуй экземпляр.
- **`rectRadius` работает только на `ROUNDED_RECTANGLE`**, не на `RECTANGLE`.
- **Градиентные заливки не поддерживаются** — вместо этого используй изображение с градиентом как фон.
- **У текстовых блоков есть встроенные внутренние отступы** — ставь `margin: 0` всякий раз, когда текст должен выровняться с фигурой, линией или иконкой на той же координате x.
- **Заметки докладчика идут в `slide.addNotes("...")`** (простой текст, один раз на слайд), никогда в текстовый блок на слайде.
- **Держи диаграммы нативными.** Используй `addChart()` для всего, что PowerPoint умеет чертить (передавай массив `{type, data, options}` для комбо). Для нативных возможностей PowerPoint, которые библиотека не раскрывает (линии тренда, планки погрешностей), вычисли дополнительные ряды сам или постобработай сгенерированный OOXML — не откатывайся к отрендеренному изображению. Только типы диаграмм, для которых у PowerPoint нет нативной формы (Sankey, network, chord), идут как изображения.
- **Диаграммы по умолчанию рендерятся голыми** — без заголовка, без подписей данных, с устаревшей палитрой. Задавай `showTitle` + `title`, `showValue: true` + `dataLabelPosition`, `chartColors: [...]` из своей палитры, и приглуши рамку (`catAxisLabelColor`/`valAxisLabelColor`, `valGridLine: { color, size }`, `catGridLine: { style: "none" }`, `showLegend: false` для одного ряда).
- **На накопительной (stacked) линейчатой или столбчатой диаграмме `dataLabelPosition` должен быть `ctr`, `inEnd` или `inBase`.** `outEnd` **портит файл**.
- **Комбо-ряд с `secondaryValAxis`/`secondaryCatAxis` требует и `valAxes`, и `catAxes` в опциях диаграммы, по две записи каждый.** Без них pptxgenjs пишет *id* осей, которые никогда не объявляет, и PowerPoint **отбрасывает такую диаграмму** и сообщает о файле как о повреждённом. Передать только `valAxes` недостаточно.
- **После `writeFile()` запусти `python scripts/office/validate.py deck.pptx`.** Он сообщает о двух дефектах диаграмм выше и о дефектах XML слайдов, которые PowerPoint отвергает, и называет исправление для каждого. Чини их в своём генераторе, а не ручной правкой упакованного XML.
- **Никогда не переупорядочивай детей `<p:presentation>`.** pptxgenjs пишет `<p:notesMasterIdLst>` сразу после `<p:sldIdLst>` и направляет оба мастера на одну часть темы. PowerPoint это спокойно читает — сдвинь элемент, и тот же дек перестаёт открываться.
- **Иконки:** рендерь `react-icons` в SVG (`ReactDOMServer.renderToStaticMarkup`), растеризуй через `sharp` при ≥256px и вставляй через `addImage({ data: "image/png;base64," + buf.toString("base64") })` — префикс `image/png;base64,` обязателен (`react-icons`, `react`, `react-dom` и `sharp` предустановлены — `npm install react-icons react react-dom sharp` только если require падает).

## Редактирование существующих деков и шаблонов

Сначала выбери макеты: `python scripts/thumbnail.py template.pptx template-thumbs` записывает подписанную сетку всех слайдов и печатает созданные файлы — `template-thumbs.jpg`, разбиваясь на `template-thumbs-N.jpg` после 12 слайдов. **Всегда передавай этот второй аргумент, названный по деку.** По умолчанию он `thumbnails`, поэтому два дека, обработанные в одном каталоге, молча перезаписывают сетки друг друга — сетки первого дека просто исчезают (только для анализа шаблона — визуальному QA нужны полноразмерные рендеры из раздела [Конвертация в изображения](#конвертация-в-изображения); скрипт принимает только `.pptx`, поэтому сначала скопируй `.potx` под именем `.pptx`). Используй его вместе с `markitdown`, чтобы сопоставить каждый раздел контента со слайдом шаблона, и варьируй макеты — не клади каждый раздел на один и тот же слайд «заголовок и маркеры».

```bash
python3 -c "import sys,zipfile; zipfile.ZipFile(sys.argv[1]).extractall('unpacked')" deck.pptx
python scripts/add_slide.py unpacked/ slide2.xml --after slide2.xml   # duplicate a slide (or slideLayoutN.xml); prints the new slide's path
# reorder / delete slides = edit <p:sldIdLst> in ppt/presentation.xml
python scripts/clean.py unpacked/                                     # after deletions: removes orphaned slides, media, rels
# edit slide content in ppt/slides/slideN.xml
(cd unpacked && rm -f ../out.pptx && zip -Xr ../out.pptx .)           # zip from INSIDE the dir; rm first or deleted parts survive
python scripts/office/validate.py out.pptx --original deck.pptx
```

- **Выполняй всю структурную работу — добавление, удаление, переупорядочивание — до правки содержимого любого слайда.** `add_slide.py` копирует файл слайда дословно, поэтому дублирование после правки клонирует отредактированное содержимое; а `clean.py` удаляет любой слайд, отсутствующий в `<p:sldIdLst>`, включая тот, который ты только что написал.
- **Никогда не копируй файл слайда вручную** — `add_slide.py` выполняет всю регистрацию, нужную новому слайду, и сообщает, что создал (`Created ppt/slides/slide17.xml from slide2.xml`). Он также работает напрямую с файлом: `add_slide.py deck.pptx slide2.xml -o out.pptx` — **передавай `-o`, иначе он перезапишет входной дек на месте.** Дублированный слайд по-прежнему *ссылается* на части диаграмм/SmartArt/встроенных объектов источника, а не клонирует их, поэтому правка диаграммы одного слайда меняет и другой.
- **Если ты используешь `python-pptx`**, три вещи, которых он не сделает: продублировать слайд (его единственная точка входа — `add_slide(layout)`), сохранить форматирование через `text_frame.text = "..."` (это схлопывает абзац в один нестилизованный run — присваивай `run.text` вместо этого), или прочитать SVG/EMF, которые использует большинство шаблонной графики (`add_picture` бросает `UnidentifiedImageError`).
- Устаревший `.ppt` сначала нужно конвертировать: `python scripts/office/soffice.py --headless --convert-to pptx file.ppt`. Шаблоны `.potx` распаковываются и упаковываются идентично — сохраняй расширение `.potx` на выходе.
- Чтобы переиспользовать иконку или изображение из шаблона, продублируй слайд или макет, который их уже содержит.

При заполнении шаблона:

- Если ты пишешь XML-трансформацию, парси через `defusedxml.minidom` — круговой прогон OOXML через `xml.etree.ElementTree` переписывает префиксы пространств имён и портит дек.
- **Слоты шаблона ≠ элементы источника.** Если шаблон показывает 4 члена команды, а у тебя 3, удали всю группу 4-го члена (изображение + текстовые блоки), а не только его текст — затем проверь осиротевшую графику на QA.
- Один `<a:p>` на элемент списка — никогда не склеивай элементы в один абзац. Копируй соседний `<a:pPr>`, чтобы сохранить интервалы, и ставь `b="1"` на `<a:rPr>` заголовков, подзаголовков разделов и встроенных меток (`Status:`, `Owner:`).
- Пусть маркеры наследуются от макета; добавляй `<a:buChar>`, `<a:buAutoNum>` (нумерация) или `<a:buNone>` только для переопределения — никогда буквальный `•` в тексте.
- Текст с ведущими или завершающими пробелами требует `xml:space="preserve"` на своём `<a:t>`.

## Идеи дизайна

**Не создавай скучные слайды.** Простые маркеры на белом фоне никого не впечатлят. Рассматривай идеи из этого списка для каждого слайда.

### Перед началом

- **Выбери смелую палитру, продиктованную содержанием**: палитра должна ощущаться созданной для ЭТОЙ темы. Если твои цвета так же «работают» в совершенно другой презентации, ты выбрал недостаточно специфично.
- **Доминирование вместо равенства**: один цвет должен доминировать (60–70% визуального веса), с 1–2 поддерживающими тонами и одним резким акцентом. Никогда не давай всем цветам равный вес.
- **Контраст тёмное/светлое**: тёмный фон для титульного и финального слайдов, светлый для контента (структура «сэндвич»). Или полностью тёмная гамма ради премиального ощущения.
- **Придерживайся визуального мотива**: выбери ОДИН отличительный элемент и повторяй его — скруглённые рамки изображений, иконки в цветных кругах. Проведи его через каждый слайд. **Не используй цветную полосу или акцентную полоску как мотив** (см. список «Избегай»).

### Цветовые палитры

### Для каждого слайда

**Каждому слайду нужен визуальный элемент** — изображение, диаграмма, иконка или фигура. Текстовые слайды забываются.

**Варианты макета:**
- Две колонки (текст слева, иллюстрация справа)
- Строки «иконка + текст» (иконка в цветном круге, жирный заголовок, описание ниже)
- Сетка 2x2 или 2x3 (изображение с одной стороны, сетка контентных блоков с другой)
- Изображение в обрез (вся левая или правая сторона) с контентом поверх

**Подача данных:**
- Крупные выноски статистики (большие числа 60–72pt с маленькими подписями ниже)
- Колонки сравнения (до/после, плюсы/минусы, варианты бок о бок)
- Таймлайн или схема процесса (нумерованные шаги, стрелки)

**Визуальная полировка:**
- Иконки в маленьких цветных кругах рядом с заголовками разделов
- Курсивный акцентный текст для ключевых чисел или слоганов

### Типографика

**Имена шрифтов, которые ты пишешь в .pptx, рендерятся PowerPoint пользователя, а не этой средой.** Твоё визуальное QA рендерится через LibreOffice, который подставляет шрифты, которых у него нет, — и для некоторых шрифтов замена имеет другую ширину, поэтому твой QA-превью может показать переполнение текста (или его отсутствие), которого в реальном деке не будет. Чтобы QA оставалось достоверным:

- **Безопасные шрифты** (рендерятся с точной шириной в QA *и* поставляются с Office): **Arial, Calibri, Cambria, Times New Roman, Courier New, Bookman Old Style, Century Schoolbook**. Используй их для основного текста и всего, где важна вместимость.
- **Заголовки с характером при нулевом QA-риске**: сочетай безопасный serif-заголовок (Cambria, Bookman Old Style, Century Schoolbook) с безопасным sans-телом (Calibri или Arial). Получаешь визуальный контраст без потери надёжных проверок переполнения.
- **Если пользователь просит шрифт вне безопасного списка** (например, Georgia или Trebuchet MS): используй его там, где просил пользователь, но размеры таких контейнеров задавай с дополнительным запасом (~10%) и не доверяй QA-проверке вместимости на этих элементах — превью этого шрифта приблизительно. Если пользователь не указал, предпочитай шрифты из безопасного списка для основного текста.
- **QA-ненадёжные шрифты** (у замены другая ширина — проверки переполнения могут ошибаться): Georgia, Trebuchet MS, Impact, Arial Black, Garamond, Consolas, Palatino Linotype. Подстановка Calibri Light варьируется по средам; считай его QA-ненадёжным. Годятся для заголовков/акцентов с запасом; не доверяй QA-вместимости на них.
- **Никогда не бери Aptos по умолчанию** — дефолт Office после 2023 года не имеет метрически совместимой замены здесь *и* отсутствует в старых установках Office, поэтому ненадёжен с обеих сторон.

| Элемент | Размер |
|---------|------|
| Заголовок слайда | 36–44pt жирный |
| Заголовок раздела | 20–24pt жирный |
| Основной текст | 14–16pt |
| Подписи | 10–12pt приглушённый |

### Интервалы

- Минимальные поля 0.5"
- 0.3–0.5" между контентными блоками
- Оставляй воздух — не заполняй каждый дюйм

### Избегай (частые ошибки)

- **Не повторяй один и тот же макет** — варьируй колонки, карточки и выноски между слайдами
- **Не центрируй основной текст** — выравнивай абзацы и списки влево; центрируй только заголовки
- **Не экономь на контрасте размеров** — заголовкам нужно 36pt+, чтобы выделяться на фоне тела 14–16pt
- **Не бери синий по умолчанию** — выбирай цвета, отражающие конкретную тему
- **Не смешивай интервалы случайно** — выбери зазоры 0.3" или 0.5" и используй последовательно
- **Не стилизуй один слайд, оставив остальные простыми** — доведи стиль до конца или держи простоту везде
- **Не создавай текстовые слайды** — добавляй изображения, иконки, диаграммы или визуальные элементы; избегай голого «заголовок + маркеры»
- **Не забывай про внутренние отступы текстовых блоков** — выравнивая линии или фигуры по краям текста, ставь `margin: 0` на текстовый блок или сдвигай фигуру с учётом отступа
- **Не используй низкоконтрастные элементы** — иконкам И тексту нужен сильный контраст с фоном; избегай светлого текста на светлом фоне и тёмного на тёмном
- **НИКОГДА не используй акцентные линии под заголовками** — это фирменный признак сгенерированных ИИ слайдов; используй пустое пространство или цвет фона
- **НИКОГДА не добавляй декоративные цветные полосы или акцентные полоски** — сюда входят: полосы верхнего/нижнего колонтитула на всю ширину слайда, вертикальные полосы сайдбара вдоль края слайда, тонкие акцентные полоски вдоль одного края карточки или контентного блока и «односторонние границы» на прямоугольниках. Они читаются как ИИ-заполнитель. Если хочешь выделить карточку, используй мягкий фоновый оттенок, тень или иконку — не полоску по краю.
- **Не бери кремовый/бежевый фон по умолчанию** — когда фон не задан, используй белый (`FFFFFF`) или фирменную палитру пользователя; избегай тёплых нейтральных дефолтов вроде `F5F5DC`, `FAF0E6`, `FAEBD7`, `FFF8E1`
- **Не сдавай текст, переполняющий свою фигуру** — если текст не влезает, уменьши размер шрифта, раздели на слайды или увеличь контейнер; никогда не оставляй контент обрезанным или вылезающим за границы

## QA (обязательно)

Твой первый рендер обычно содержит несколько реальных проблем — наложения, переполнения, смещения. Найди и исправь их, перерендерь только изменённые слайды и остановись.

### QA содержимого

```bash
markitdown output.pptx
```

Проверь на пропущенный контент, опечатки, неверный порядок.

**При использовании шаблонов проверяй остатки текста-заглушки:**

```bash
markitdown output.pptx | grep -iE "\bx{3,}\b|lorem|ipsum|\bTODO|\[insert|this.*(page|slide).*layout"
```

Если grep что-то возвращает, исправь это, прежде чем объявлять успех.

### QA файла (обязательно)

```bash
python scripts/office/validate.py output.pptx                      # built from scratch
python scripts/office/validate.py output.pptx --original src.pptx  # built from a template
```

**Если дек получен из шаблона, всегда передавай `--original`.** Шаблон сам может
содержать части, которые XSD отвергает, поэтому голый запуск может сообщить о сбоях,
которых ты не вызывал, — и подлинная регрессия может спрятаться среди них. `--original`
берёт за базу проверки схемы и слайдов по шаблону, подавляя ошибки, которые там уже были.
Структурные проверки — связи, content types, диаграммы — игнорируют `--original` и в любом
случае сообщают о проблемах, унаследованных от шаблона, поэтому читай их по существу.

pptxgenjs испускает XML диаграмм, который PowerPoint отказывается открывать, а все
остальные инструменты принимают: python-pptx открывает такие деки, LibreOffice их
рендерит, XSD их пропускает. Каждый сбой называет своё исправление. Чини в генераторе
и пересобирай.

### Визуальное QA

Конвертируй слайды в изображения (см. [Конвертация в изображения](#конвертация-в-изображения)) и осмотри каждое. После долгого взгляда на генерирующий код ты склонен видеть то, что ожидаешь, а не то, что отрендерилось, поэтому смотри на изображения свежим взглядом (субагент здесь работает хорошо, если он у тебя есть). Видимые пользователю дефекты, которые нужно искать:

- **Переполнение текста или текст, обрезанный на границе блока или слайда — проверяй это первым.** Это самый частый дефект, и он всегда виден пользователю. (Для шрифта, который превьюер рендерит ненадёжно согласно разделу «Типографика», превью приблизительно: доверяй запасу ~10%, который ты оставил, а не видимой вместимости.)
- Наложение элементов (текст сквозь фигуры, линии сквозь слова, сложенные друг на друге элементы)
- Ссылки на источники или колонтитулы, сталкивающиеся с контентом выше
- Элементы слишком близко (зазоры < 0.3") или карточки/разделы почти касаются друг друга
- Неровные зазоры (большая пустая область в одном месте, теснота в другом)
- Недостаточный отступ от краёв слайда (< 0.5")
- Колонки или похожие элементы, выровненные непоследовательно
- Низкоконтрастный текст (например, светло-серый текст на кремовом фоне)
- Съехавшая декорация шаблона после замены текста — например, подчёркивание заголовка, позиционированное под одну строку, когда заменённый заголовок перенёсся на две
- Низкоконтрастные иконки (например, тёмные иконки на тёмном фоне без контрастного круга)
- Слишком узкие текстовые блоки, вызывающие чрезмерный перенос строк
- Остатки контента-заглушки

## Конвертация в изображения

Конвертируй презентации в отдельные изображения слайдов для визуального осмотра:

```bash
python scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 150 output.pdf slide
ls -1 "$PWD"/slide-*.jpg
```

**Передавай абсолютные пути, напечатанные выше, напрямую в инструмент просмотра.** `rm` убирает устаревшие изображения прошлых запусков. `pdftoppm` дополняет нулями по числу страниц: `slide-1.jpg` для деков до 10 страниц, `slide-01.jpg` для 10–99, `slide-001.jpg` для 100+.

**После исправлений перезапусти все четыре команды выше** — PDF должен быть перегенерирован из отредактированного `.pptx`, прежде чем `pdftoppm` сможет отразить твои изменения.
