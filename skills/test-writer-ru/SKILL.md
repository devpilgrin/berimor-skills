# Написание тестов

1. **Прочитай код целиком**, прежде чем писать первый тест — сигнатуру,
   побочные эффекты, обработку ошибок. Не тестируй код, которого не
   понял.
2. **Проверяй поведение, не реализацию.** Тест обязан пережить
   рефакторинг, который не меняет наблюдаемое поведение. Не проверяй
   внутренние детали (приватные поля, порядок вызовов), если это не
   часть контракта.
3. **Обязательные случаи**: happy path; минимум один граничный случай
   (пустой вход, ноль, максимум); минимум один случай ошибки/отказа,
   если функция может отказать.
4. **Один тест — одно утверждение по смыслу.** Имя теста описывает, что
   проверяется и при каком условии, не «test1»/«test_foo».
5. **Прогони тесты реально** после написания — покажи результат
   прогона, не только текст кода. Красный тест до фикса — это нормально
   и полезно (доказывает, что тест вообще что-то проверяет), но
   финальное состояние обязано быть зелёным или явно объяснённым, если
   нет.

Не пиши тесты, которые всегда проходят независимо от кода (тавтологичные
проверки) — это хуже, чем отсутствие теста: создаёт ложное чувство
покрытия.
